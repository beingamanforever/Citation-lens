# Benchmarks

The checked-in [benchmark.json](benchmark.json) is generated by:

```bash
uv run --no-project --with tiktoken python scripts/benchmark.py --tokens > docs/benchmark.json
```

Omit `--tokens` and `--with tiktoken` for dependency-free byte measurements.
The reference tokenizer is `cl100k_base`; counts exclude SDK framing, host prompts,
images and inference and are not actual Codex/Claude usage.

## Paired efficiency fixtures

The same two queries and two providers supply four bounded searches in isolated cold caches.
Both paths call the actual search entrypoint and use production pacing.
Each successful search returns ten fabricated normalized records.
The batch pages every retained candidate before complete costs are counted.

| Scenario | Scalar calls / batch calls, complete | Complete bytes, scalar / batch | Reference tokens, scalar / batch |
| --- | --- | ---: | ---: |
| Duplicate-heavy | 4 / 1 | 37,741 / about 10,500 | 7,192 / about 2,100 |
| Disjoint | 4 / 4 | 37,771 / about 41,900 | 7,192 / about 8,400 |
| One provider attempt fails | 4 / 3 | 28,376 / about 31,800 | 5,409 / about 6,400 |

All pairs retain identical DOI sets and make four HTTP requests; the outage remains one failed attempt in both paths.
The first batch response contains ten cards and takes one tool call in every scenario.
Disjoint and outage runs cost more bytes/tokens when every page is read because provenance is retained.
The overlap fixture is about 70% smaller in reference tokens; it is not a universal improvement.
Observed fixture latency is about 1.23 seconds scalar versus 1.15 seconds batched,
with Semantic Scholar's 1.05-second host pacing limiting gains.
These exclude inference, and wall-clock values vary by machine.

Paged reading retains the same 150,010-character document across thirteen responses.
Returning the overview once reduces 430,541 to 175,865 bytes (59.15%),
and 75,974 to 30,032 reference tokens.
The baseline reconstructs the previous reply contract, which repeated headings and twelve figure captions on every page.
Every text character, source warning and figure remains accessible; this is not lossy summarization.

The actual serialized five-tool schema was 4,538 bytes before the batch extension and 4,772 bytes afterward.
We keep five tools; host tool search remains responsible for deferring their definitions.
Schema counts are not included in the response-token table.

[Live programmatic batch](live-batch-search.json) records the SDK client searching two variants across OpenAlex and arXiv,
paging results inside Python and printing only five cards plus all attempt coverage.
It is a workflow check, not a paired model-quality evaluation.

## Search versus citation expansion

A deterministic **synthetic** corpus supplies two search hits and seven citation
links. Both workflows start from the same hits; Citation Lens runs the real
`Graphs.expand` implementation, one hop in both directions. This is a graph-code
comparison, not a run of a Codex or Claude model.

| Output | Search-only fixture | With citation expansion |
| --- | --- | --- |
| Papers | Tiled exact attention; Efficient attention survey | Both seeds plus Transformer foundations, Decode-aware attention, Fresh attention kernel and Shared cache methods |
| Count | 2 | 6 |
| Citation edges | 0 | 7 |
| Neighbor lookups | 0 | 4 |
| Full text downloaded | 0 | 0 |

All paper names and IDs in this fixture are fabricated. The graph retains shared
ancestors once, stores citing → cited edges and includes the new zero-citation
paper. The additional nodes are not evidence of improved relevance or recall.
Ordinary agents can follow citations manually; this fixture does not test their ability.

## Context payload and cache

Twenty fabricated records contain repeated method/result prose (about 51,000
characters each). Both payloads use the same compact UTF-8 JSON serializer.
The full dump includes metadata, complete abstracts and fabricated text; cards
contain selected metadata and at most 650 abstract characters.

| Measurement | Result |
| --- | ---: |
| Full dump | 1,096,121 bytes |
| Cards | 18,201 bytes |
| Reduction | 98.34% |
| Cold batch: 8 requests | 1,140.181 ms |
| Warm batch p50 / p95 | 0.129 / 0.302 ms |
| Additional upstream calls across 30 warm batches | 0 |

Cache latency is synthetic: 80 ms fixture response latency and the production
150 ms per-host pacing. Warm values are local cache measurements; timings vary
by machine. These are **bytes, not tokens**. Images, host prompts, MCP framing,
subsequent selected reads, reasoning and synthesis are excluded. Full dumps of
real papers have different lengths. The reduction is a fixture result, not a
universal percentage.

## Live provider run: 8 October 2026

[live-benchmark.json](live-benchmark.json) records a successful OpenAlex run for `FlashAttention`.
Five search hits included FlashAttention, FlashAttention-2, a second publication record
for FlashAttention, FlashAttention for Scalable Vector Architectures and FLASH-D.
Expanding the first three seeds added relationships to PagedAttention, Lost in the Middle
and other candidates: 21 total nodes and 18 directed edges.
Some neighbors are outside the intended topic and still require screening.
Different DOI records for preprint and proceedings versions can remain separate.

| Measurement | Observed result |
| --- | ---: |
| Search, one request | 590 ms |
| Additional expansion, six requests | 1,315 ms |
| Title-matched readable papers | 2 of 2 attempted |
| Paired cards / extracted text plus cards | 2,011 / 218,270 bytes |
| Paired reduction | 99.08% |
| Search, expansion and full-text errors | 0 |

The paired documents are FlashAttention and FlashAttention-2, extracted from arXiv HTML.
Sources, character counts and extraction warnings are included in the JSON.
Timings are one observation each, not latency distributions or host-level measurements.
An earlier broad-query exploratory run retrieved unrelated psychology papers and publisher
403 errors; narrowing the query and screening remain necessary.
This result does not establish relevance, completeness or better research conclusions.

`scripts/live_benchmark.py` performs a fresh OpenAlex search, one-hop expansion
from three unscreened seeds, and a paired card/full-text comparison for at most
five readable papers whose titles contain the query. It reports titles, IDs, edges, timings, request counts,
failures and the exact paired byte definition. No API key is needed by the runner;
providers may reject anonymous traffic. Release CI uploads the JSON even when
providers fail. Reproduce with:

```bash
uv run --no-project python scripts/live_benchmark.py > live-benchmark.json
```

This run is separate from the toy fixture. It tests provider workflow behavior,
not an agent's research quality. Live results are attached to the release when
available; CI observations may differ from this recorded run.
Do not infer SOTA completeness or an accuracy uplift from paper counts.
Actual Codex/Claude token and research comparisons require the paired, human-graded
protocol in [EVALUATION.md](EVALUATION.md).
